# Admin 内的博客检查与优化

入口：后台「博客管理」。本功能复用正常运行的 Admin，无需运行 `blog-audit.sh`、导出SQL或启动第二个 Java 进程。

## 整体扫描

点击「扫描全部文章」，页面显示准备状态、已检查篇数和总数。扫描草稿及已发布文章，排除已归档文章；不会修改文章，也不会调用 AI。

结果显示需审阅篇数、缺来源/限制/实例、正文过薄等数量，可按问题筛选，点击「检查与优化」打开相应文章。问题可重叠，需审阅数量也可能包含只需复核的相似标题。

「选题重叠候选」另外比较存在问题文章的标题，最多显示100对。它不改变发布查重阈值，不是语义模型，不会自动归档或合并。检查清单未收录的文章不参加这一候选分析。是否合并需对照正文，考虑独有信息与旧URL的流量；保留现有归档/恢复操作及其确认提示。

## 单篇检查与一键优化

1. 列表「检查」会打开编辑器并检查当前文章；编辑器「检查重复与质量」检查当前未保存内容。
2. 列表「优化」会打开编辑器、检查文章并定位到「文章优化」区域；打开入口不会自动调用 AI。编辑器提前检查 AI 配置，缺少密钥时禁用「一键优化」并显示配置提示，不影响检查和编辑。填写优化要求和已核实的参考资料（可选），点击「一键优化」。当前标题、摘要、正文、元数据及所填资料会发送到配置的 DeepSeek 服务，使用该账号额度。
3. 等待任务完成，查看优化稿安全预览、修改说明、优化前后词数及规则阻断项数量、剩余重复匹配。
4. 点击「应用到编辑区」或「放弃优化稿」。应用不会自动保存；生成期间原文发生变化时会阻止覆盖，需要基于最新原文重新生成。
5. 核实事实、引用和实例后保存或发布。已发布文章的保存仍须通过质量/查重门槛；尚不满足时可先撤回为草稿继续整理。保存应用的优化稿时会固化 AI 辅助来源，不改写原创建者记录，不自动改动URL、作者或发布状态。

后台优化会自动定位候选官方文档并实际读取页面正文，将读取内容交给 AI 整理支持结论的引用，并把引用说明写入正文参考资料小节。不需要管理员预先填写来源。候选定位由 AI 完成，不依赖额外搜索 API，也不等同于搜索引擎全网检索。

目前支持 RFC Editor、IANA、ICANN、MDN、Cloudflare 开发文档、Let's Encrypt、OpenSSL 文档、Microsoft Learn、AWS 文档、Google Cloud 和 W3C 的指定官方域名。只读取 HTTPS HTML/文本页面，不跟随重定向，不执行网页脚本。最多尝试 6 个页面、采用 4 个，每页限 512 KiB；长文保留开头并按标题关键词选取正文片段，发送给 AI 的每页资料不超过 16000 字符。片段选择可能遗漏依据，不能替代完整文档审阅。页面无法读取或题材不受支持时，会明确列出缺口，不伪造引用；可以补充官方链接及摘录后重试。现有文章中未读取的旧链接会保留，但不会标为已核实。

每次优化最多调用两次 AI（定位文档、编辑文章），可能使用更多额度，总耗时最多约 6 分钟。读取网页不等于事实认证，也不等于执行过代码示例；仍需审核关键结论。程序会清洗生成的 HTML，不会直接执行模型返回的脚本。

## 任务状态与限制

- 每个 Admin 实例同一时间只执行一个扫描或优化任务，避免重复消耗内存与AI额度。其他请求得到忙碌提示。
- 只有提交任务的管理员能读取该任务。网络中断时使用「恢复查看」继续获取相同任务，避免重复生成。
- 任务结果暂存在当前实例内存中；结果从完成时起保留30分钟，新任务不会覆盖旧结果。最多暂存10项任务，容量满时会拒绝新任务并提示等待过期。刷新或关闭页面会失去当前页面的任务ID及未保存优化稿；完成编辑后及时保存。服务重启后需重新操作；多实例需要会话粘性或后续改为共享任务存储。
- AI 请求限制150秒，响应限制512 KiB；单次原文最多60,000字符。扫描沿用4,000篇/32 MiB正文容量上限及单篇1 MiB限制，超限失败，不返回部分结果冒充完整报告。
- 扫描期间尽量避免其他编辑或生成任务同时写入，结果反映扫描时状态，不能替代保存时重新检查。编辑保存后页面会提示重新扫描。

## 生产配置与部署

先确保已执行 `alter_blog_content_review.sql` 和 `alter_blog_ai_provenance.sql`。本次功能不新增数据库迁移。

在 `/usr/java/config/admin/application-prod.properties` 添加或更新（避免重复定义）：

```properties
ai.deepseek.api-key=${DEEPSEEK_API_KEY:}
ai.deepseek.base-url=https://api.deepseek.com/v1
ai.deepseek.model=deepseek-chat
```

将真实 `DEEPSEEK_API_KEY` 设置在 Admin 已使用的私有环境文件或启动环境中，不要放入仓库或浏览器。缺少密钥仍可扫描及检查，优化会给出明确配置提示。

通过 Jenkins 构建部署新版 Admin 后重启。前端页面包含在 Admin JAR 中；部署后刷新后台页面。若有多个实例，应保证请求路由至同一实例，否则轮询可能报任务不存在。

验收：扫描完成并能筛选问题；单篇检查显示未保存修改的问题；优化生成后数据库原文不变；应用后才进入编辑区，保存后保留AI说明；归档稿隐藏优化入口；网络故障可恢复查看，失败不会显示成功。

本地验证包含Java回归、MySQL编辑事务集成测试和Node页面运行测试。真实AI调用需要生产或测试账号密钥；自动测试使用模拟客户端，不消耗线上额度。
