# 博客查重与内容审查

本次升级阻止新增重复稿件和不完整内容发布，并为历史文章提供只读审计。它不会自动重写、合并、删除或下架正式文章。

## 上线顺序

1. 备份 `WEB_BLOG_POST`，记录当前 Web/Admin 版本。暂停编辑写入及 AI 生成任务，避免新旧发布逻辑混用。
2. 依次执行 `doc/alter_blog_content_review.sql` 和 `doc/alter_blog_ai_provenance.sql`。前者创建查重锁；后者添加 `AI_GENERATED` 并回填能确认的 AI 来源，保留署名、创建者和正文。两份迁移均可重复执行。
3. 分别部署 Web 和 Admin，再恢复写入。不要把迁移作为常规 Jenkins 流水线的隐式副作用。
4. 验证后台“检查重复与质量”、保存草稿、发布和编辑已发布文章。重复稿件仍可在草稿中修改，但不能发布；不完整的已发布文章需先撤回，再编辑，或一次补齐后保存。
5. 回滚应用时保留锁表和新增列。旧版本不认识归档状态，回滚后应保持博客编辑入口停用，直至部署兼容版本，避免旧后台把归档文章重新发布。

数据库锁在编辑事务开始时获取，直到事务提交或回滚才释放，以避免两个 Web/Admin 实例同时通过查重。锁表缺失时写入会报错，不会跳过查重。部署过程中必须停止旧版写入者；直接 SQL 导入及绕过编辑服务的写入不受应用锁保护。

## 历史文章只读审计

在正式环境使用已有数据库配置运行新 Admin JAR。此命令无 apply 模式，不改文章；`blog-audit` profile 禁用 Admin 定时任务，且必须以非 Web 模式运行。建议使用数据库只读账号（通过现有外部配置提供凭据），不要把密码写进命令行。

```bash
set -o pipefail
java -jar wesite-admin/target/wesite-admin-1.0.0.jar \
  --spring.profiles.active=prod,blog-audit \
  --spring.main.web-application-type=none \
  --wesite.blog.audit.enabled=true \
  2>&1 | tee blog-content-audit.log
```

成功后日志中包含 `Blog content audit completed:` JSON，列出参与查重的文章总数和需要处理的文章。每项包含 ID、slug、标题、状态（0 草稿、1 已发布）、阻断项、提醒和重复匹配。状态 2 为已归档，不计入扫描总数。报告不包含正文；错误退出或缺少完成日志表示审计未完成，不可当作“没有问题”。执行审计前应完成上述迁移，再使用新 Admin JAR。

处理建议：

- `SAME_CONTENT` / `NEAR_CONTENT`：对照全文确认，选择信息最完整、链接最稳定的保留版本。在后台把其他版本“归档重复稿”，然后编辑保留文章，补入独有内容。归档保留原文和原 slug、发布时间，能随时查看并恢复为草稿；它不会自动合并正文，也不会创建重定向。归档后旧地址返回 404，如需维持旧链接，应事先配置对应 301 跳转。
- `SAME_TITLE`：比较正文是否确属同一问题，合并重复内容；独立内容需明确不同标题和范围。
- `SIMILAR_TITLE`：仅是选题提醒，不自动阻断。确认是否有独立读者问题与新增价值。
- 缺少来源、实例、限制或正文过薄：保留草稿并重写。优先完善核心文章，不按数量批量发布。

## 检查规则及边界

- 查重覆盖所有未删除、状态为草稿或已发布的文章，不只看最近标题；比较时排除当前文章自身及已归档文章。普通撤回仍为草稿，继续参与查重，不能代替归档。恢复归档文章只回到草稿，立即重新参与查重，且必须重新通过发布检查。
- 标题经 Unicode NFKC、大小写、空白及标点归一化后比较。正文经 HTML 安全清洗并提取文字后计算 SHA-256，相同文字的排版差异不影响检测。
- 80 词以上正文使用连续 5 词片段集合的 Jaccard 相似度，达到 0.85 视为高度相似。标题词集合相似度达到 0.75 仅提醒。这不是语义模型，完全改写的重复选题仍可能漏检，也可能出现误报，需人工对照。
- 发布及编辑已发布文章要求：标题/摘要/搜索描述完整；至少 200 词正文说明（代码和表格不计）；至少两个小节；非空代码、表格或有序步骤；限制/注意事项/排查小节；至少一个站外 HTTPS 参考链接；无常见待补充占位文字。
- 当前词数规则针对站点英文博客。中文内容不适用英文分词门槛；上线其他语言前应增加对应分词规则。
- **完整性检查不是事实验证。** 系统不会打开引用链接、验证来源权威性、执行示例或认证测试结果。编辑必须逐条核对关键事实和一手来源，明确示例与实测的区别，检查时效性和适用范围。
- AI 仅生成草稿。选题预检查减少重复生成，入库前在锁内再次查重；草稿可暂时不满足发布完整性要求，以便人工补充来源和实验结果。
- 当前为低频博客编辑设计：每批读取 100 篇，最多 4,000 篇 / 32 MiB 正文，单篇最多 1 MiB。超限报错，不会以部分扫描结果放行发布。规模增大前应改为持久化指纹和分批相似检索。
- 列表在时间排序之后增加 ID 排序，修复同一发布时间的顺序不稳定；翻页期间有新增文章时，偏移分页仍可能移动，这是另一个问题。

## 验证命令

```bash
mvn -pl wesite-web,wesite-admin -am '-Dtest=Blog*,AiBlogTaskTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
node --test wesite-admin/src/test/js/blog-editor-runtime.test.js
```

`BlogContentReviewMySqlTest` 使用临时 MySQL 8.4 容器验证迁移可重复执行、并发不同 URL 的正文去重、并发相同标题去重、归档与恢复的完整编辑流程，以及 AI 来源回填和持久化。没有 Docker 时它会跳过；发布前应在具备 Docker 的环境执行并确认全部通过。

AI 来源与公开署名独立：新 AI 草稿写入 `AI_GENERATED=1`；迁移根据旧随机笔名或 `CREATE_BY=ai` 回填已知来源，普通站点署名及未知来源保持 NULL。保存旧稿时也会在修改署名前固化已识别的来源，不改写创建者记录。后台不提供修改来源字段的输入，署名更换不会撤销 AI 说明。
