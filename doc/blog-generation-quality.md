# AI 文章生成质量门槛

生成入口仍为 Web 的 `AiBlogTask` 定时任务。流程：读取人工维护的资料包及所有有效文章标题 → 有依据的选题 → 生成 → 严格解析与 HTML 清洗 → 现有质量/正文查重规则 → 独立 AI 审稿调用 → 按问题修订 → 复检 → 创建待人工审核草稿。生成不会自动发布。

## 强制行为

- 客户端仅接受 `finish_reason=stop` 且正文非空的响应。截断、响应结构错误、超时、超出 512 KiB 均停止本次任务，不自动重发付费请求；错误日志不包含服务端响应正文。
- 摘要、正文和搜索描述必须完整且顺序正确。正文清洗后再检查；重复或缺失段标记、HTML 元数据均不能直接通过。
- 至少通过现有词数、结构、实例、限制、来源和重复检查；外部引用必须在资料包的来源清单中。列入清单只说明来源可用，引用是否支持论点仍由审稿和人工核实。
- 独立审稿调用评价读者问题、解释深度、步骤及结果解读、实例真实性、限制、依据和相对于已有标题的独立价值。模型判断仍可能误判，并非事实认证或全文语义去重。
- 最多两次修订，每次重新检查。审稿 JSON 无效或结论与问题清单矛盾不能放行。最多 7 次 AI 请求（选题 1 次、写作 3 次、审稿 3 次）；超时沿用 `ai.deepseek.timeout-seconds`。
- 不合格结果不入库。日志搜索 `AI_GENERATION_REJECTED` 查看最终问题（包括格式、规则或语义审查原因）；连接、截断或资料读取失败记录任务异常。没有新增失败稿后台列表，失败结果不计为成功草稿。
- 选题对照读取全部草稿和已发布文章的标题，排除归档稿。超过 4000 篇或标题合计 60000 字符就停止生成，避免只检查部分文章却报告成功。并发写入仍由原有入库事务内查重兜底，AI 标题审稿使用生成开始时快照。

## 资料维护与范围

默认资料：`wesite-web/src/main/resources/blog/generation-evidence.txt`。目前仅覆盖 DNS 缓存、负缓存及 RDAP 查询格式，含来源、节号、摘要、审阅日期和限制。默认自动选题相应收窄，不再无资料生成投资、价格或泛安全建议。

核对来源：[RFC 1035](https://www.rfc-editor.org/rfc/rfc1035.html)、[RFC 2308](https://www.rfc-editor.org/rfc/rfc2308.html)、[RFC 9082](https://www.rfc-editor.org/rfc/rfc9082.html)。这些是范围有限的标准资料摘要，不代表覆盖后续标准修订或特定产品当前行为。

需要扩展题材时，可在 Web 私有部署配置中指定人工维护的本地 UTF-8 文件：

```properties
ai.blog.evidence-location=file:/usr/java/config/web/blog-generation-evidence.txt
```

文件最多 60000 字节。每份资料用独立一行 `Source: https://准确的一手资料地址`，随后写明 `Scope:`、`Evidence:`、审阅日期和适用限制；同时更新包顶部允许的题材范围。必须摘录或概括实际支持的事实，不能只罗列 URL。程序不会联网打开来源链接；部署方需定期复核、更新资料。默认 classpath 资料随 Web JAR 部署，无新增数据库迁移。

## 验证边界

新增固定 DNS 文章样本，使用真实规则和模拟 AI 验证完整稿、缺字段修订、引用越界、语义拒绝、无效审稿、次数耗尽、截断及容量限制。这些测试证明流程会执行门槛，并不测量真实模型准确率。

上线后应抽样检查真实生成稿，逐条核对事实和引用、按实际环境运行示例，再人工发布。首次验收记录合格率、引用错误、语义重复与修订次数；不能把模拟测试通过表述为文章质量评测通过。
