# Whose.Domains 后台优化设计

## 背景

`wesite-admin` 当前同时存在 LayuiAdmin 单页后台和未整合的 Thymeleaf 管理页面。单页路由会把未登录用户发送到 `#/user/login`，但该视图不存在；侧栏菜单仍包含大量 Layui 演示入口；用户、顶级域名、二级保留域名及联系消息页面还存在错误接口、错误表格事件、乱码或安全问题。因此，本次改造不是单一页面美化，而是认证、导航和业务页面的整体闭环。

## 目标

- 保留现有 LayuiAdmin 技术栈，不引入 Vue、React 或新的前端构建链。
- 提供可用、清晰、中文化的登录页和稳定的登录/退出流程。
- 登录后仅显示系统真实支持的菜单，每个入口都能完成对应业务操作。
- 将联系消息整合进单页后台，消除两套后台界面并存造成的割裂。
- 修复已确认的错误接口、数据保存和输出转义问题。
- 提供有业务价值的工作台和自动化回归保护。

## 非目标

- 本期不引入多角色 RBAC；所有有效管理员拥有相同菜单。
- 不迁移现有管理员密码算法，避免正式环境账号失效。
- 不改动 `wesite-web` 的 `/domain/*`、`/blog/*` 等公开 URL、索引策略或 SEO 行为。
- 不重写为新的前端框架，也不要求 Node.js 构建步骤。

## 选定方案

在现有 LayuiAdmin 单页后台上就地改造。继续使用根视图作为 SPA 宿主、Hash 路由加载静态视图、`admin.req` 访问 Spring MVC JSON 接口。移除演示菜单和演示交互，将原有真实业务页面修复并统一。

未采用的方案：

- 纯 Thymeleaf 管理后台：会重写现有域名和博客页面，回归范围较大。
- Vue/React 管理后台：需要引入依赖管理、构建、部署和维护链，超出本次目标。

## 信息架构

侧栏仅保留：

1. 工作台
2. 用户管理
3. 域名管理
   - 顶级域名
   - 二级保留域名
4. 内容管理
   - 博客文章
5. 客户服务
   - 联系消息

右上角账号菜单提供当前管理员名称、访问前台和退出登录。访问前台使用 `https://whose.domains/`，不再保留演示链接、便签、主题、消息或关于面板。

## 登录与会话

- 新增 `views/user/login.html` 独立视图，包含账号、密码、显示/隐藏密码、提交中状态和错误区域。
- 提交 `POST /login` JSON 请求。账号和密码先在浏览器端做空值检查，服务端仍是最终校验方。
- 登录失败统一返回“用户名或密码错误”，禁用账号和不存在账号不对外暴露差异。
- 登录成功后保存现有 `access_token`，清理旧标签状态，并跳转到经过白名单校验的站内 Hash 路由；非法重定向退回工作台。
- `GET /userInfo` 改为只返回 `id`、`name`、`phoneNo` 等必要展示字段，不再序列化完整 `User`。
- 任一 API 返回 401 时，统一清理 Token、缓存的管理员信息和后台标签状态，再进入登录页。
- 退出登录先调用 `GET /logout`，无论响应是否成功都清理本地会话并回到登录页。现有 JWT 仍保持无状态，本期不增加 Redis 黑名单。

## 工作台

新增聚合接口 `GET /dashboard/summary`，返回：

- 用户总数
- 顶级域名总数
- 二级保留域名总数
- 博客草稿数与已发布数
- 待处理联系消息数
- 最近博客文章
- 最近联系消息

工作台以中文数据卡片、待处理提醒和快捷入口呈现。聚合查询失败时显示可恢复错误，不阻塞其他后台页面。

## 业务功能

### 用户管理

- 按姓名或手机号查询普通用户。
- 支持新增、编辑和删除普通用户。
- 修复保存时把名称和状态写成 `null` 的缺陷。
- 服务端只允许操作 `TYPE_PERSON`，避免通过构造请求修改或删除管理员。
- 列表和详情响应避免包含密码、密钥等敏感字段；使用后台专用 DTO。

### 域名管理

- 顶级域名支持搜索、刷新和编辑联系信息。
- 二级保留域名支持搜索、新增、编辑和状态变更。
- 修复遗留 `/listing/*`、错误表格 ID、错误事件名称和英文错误文案。
- 服务端继续校验重名及所属顶级域名。

### 博客管理

- 保留现有草稿、编辑、安全预览、发布和撤回流程。
- 统一页面标题、筛选区、状态标签、确认提示与空状态。
- 保持公开博客地址和发布语义不变。

### 联系消息

- 新增 Layui 单页视图，替代未整合的 Thymeleaf 管理页。
- 支持分页、查看详情、标记处理状态和批量删除。
- 前后端统一 HTTP 方法和中文响应文案。
- 所有访客提交字段在插入 DOM 前转义，防止存储型 XSS。
- 待处理统计使用真实状态查询，不再返回固定值。

## 视觉与交互

- 使用深色侧栏、浅色内容区和克制的品牌绿色作为强调色。
- 登录页不使用大面积渐变；以品牌、系统说明和登录卡片建立层级。
- 表格操作使用文字加图标；危险操作使用红色并二次确认。
- 所有异步提交防止重复点击，并在成功或失败后给出明确反馈。
- 表单具备可见标签、键盘焦点和足够颜色对比度；主要页面适配桌面及窄屏。
- 源文件统一保存为 UTF-8，清除当前乱码文本。

## 错误处理与安全边界

- 登录错误不暴露账号是否存在、是否禁用。
- 受保护 JSON 接口继续返回统一 `ResponseJson` 401；静态 SPA 宿主仍允许加载。
- API 不直接返回带密码或密钥字段的用户实体。
- 联系消息内容必须转义后显示。
- 删除、发布、撤回等不可逆或高影响操作必须二次确认。
- 重定向仅接受以 `/` 开头且不以 `//` 开头的 Hash 内部路径。

## 测试与验收

- 控制器测试覆盖登录成功、错误密码、禁用账号、非管理员账号、用户信息脱敏和工作台统计。
- 拦截器测试覆盖缺失、无效和有效 Token，以及 401 后的前端清理契约。
- 用户控制器测试覆盖新增、编辑、查询、普通用户边界和管理员保护。
- 域名及联系消息控制器测试覆盖真实接口方法、校验、统计和状态修改。
- 静态模板契约测试验证登录视图存在、菜单只含真实路由、页面无演示接口、敏感内容经过转义。
- 运行 `mvn -pl wesite-admin -am test` 作为完整回归门禁。
- 人工验收登录、退出、直接访问受保护路由、全部菜单、窄屏菜单和主要业务增删改查。
